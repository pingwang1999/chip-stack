Four carriers, four material chains

PCB is often lumped in with chip packaging. It does not belong there. The substrate runs on build-up film with no glass reinforcement. The PCB runs on copper clad laminate, pressed from copper foil, resin and glass fabric. The two chains barely share a supplier.

The numbering is not a taxonomy. It is the order the signal actually travels. Moving outward from the die, pad pitch widens by roughly an order of magnitude at every step, and the material set changes with it. 01 is innermost, 04 is the board.

Where it binds

HBM is the only thing on this map that sits in layer 01 and layer 02 at the same time. It needs a leading-edge DRAM process to make the dies and advanced packaging to stack twelve of them, so its supply behaves unlike the rest of memory. Neither gate opening is enough on its own. Micron has put a number on that with its three-to-one input ratio, meaning HBM3E consumes roughly three times the wafer of DDR5 for the same capacity, and has said the ratio rises in later generations. Add 2026 supply already sold out against a stated ability to meet only half to two-thirds of customer demand, and the gap is not something capex alone closes.

Semiconductor front-end process

HBM stack (12 DRAM + 1 base die): A stack is only good if every die in it is good. Twelve dies in series is where the hard part of this chain lives. Suppliers: SK hynix, Samsung, Micron.

The dies in a stack (12 DRAM + 1 base die): A stack holds two kinds of die. Twelve are DRAM, made on a memory process in the memory makers' own fabs. The thirteenth is the base die at the bottom, carrying the external interface and control logic. From HBM4 it moves off the memory process onto a foundry logic process, which opens an external link in what used to be a closed memory chain.

Layer 03

IC substrate

IC SUBSTRATE / ABF · ABF film · no glass reinforcement
Full name
IC substrate, ABF substrate at the high end
Position
Between the package and the board
Purpose
Fans the fine package pitch out to something the board can actually attach to
Function
Signal fan-out, mechanical support, part of the thermal path
Materials
ABF build-up film carries no glass. The core layer is a glass-reinforced laminate. Plus copper foil, laser-drilled vias and solder balls

Where it binds

Substrate pricing moves on the same line as PCB. The core of an ABF substrate is itself a laminate, Kinsus is qualifying a T-glass plus E-glass build, and Elite Material has started shipping core material into substrates. So when glass fabric and copper foil tighten, substrates tighten with them. Unimicron and Ibiden capacity is absorbed by AI GPUs and ASICs, which is why the next-generation AMD server CPU substrate went to Nan Ya PCB.

Where it binds

The tightest input this year is not an exotic one. It is ordinary E-glass fabric, up more than 80% in the first half, which has held laminate makers at around 70-75% utilisation with order books they cannot fill. High-end copper foil tells the same story, with HVLP4 demand well above what the Japanese incumbents plus Co-Tech can put out. Look one step further up and the real gate is equipment. High-end looms are quoting into 2030 and treaters run 18 to 24 months, so how fast this layer expands is decided by the machine builders.

Demand amplification from a laminate grade step

Demand for copper clad laminate (CCL) relative to an M6-grade board, as the product of three factors: layer count × board area × yield loss.

ScenarioLayersLayer multiplierArea multiplierYield-loss multiplierCCL demand vs M6
M6 — baseline12–161×1×1×1×
M8 — base case24–322×2–2.5×1.15–1.3×4.6–6.5×
M8 — GB300 largest board, upper bound402.5–3.33×3–5×1.15–1.3×8.6–21.6×
  • M8 base case: Layer counts pair 12 to 24 and 16 to 32, not crosswise. Doubling layer count also doubles board thickness.
  • M8 GB300 largest board, upper bound: 8.6 to 16.3× off a 16-layer base, 11.5 to 21.6× off a 12-layer base. This assumes three extremes land together, so it is a bound rather than a forecast and should be read separately from the base case.

Layer count is set by the design and is effectively known. Yield and size are the only two variables that move with process maturity, so those are the two questions that decide where in the range a programme lands.

Downstream link: because doubling layer count physically means stacking more copper foil, the CCL demand multiple carries through to high-end copper foil at roughly the same multiple (Mitsui Kinzoku, Co-Tech Development). Cost share and volume multiple are different things; they connect here only because the layer factor is itself a count of foil sheets.

HBM demand cascade

Pick a rack, set how many ship in a year, and the chain works down to the HBM stacks and DRAM dies behind them. The number you set is a scenario, not a forecast.

Formula: racks × GPU packages per rack × HBM stacks per GPU = HBM stacks; × DRAM dies per stack = DRAM dies. HBM capacity = racks × GPUs per rack × GB per GPU (1 PB = 1,000,000 GB). Bits = GB × 8 (1 Eb = 1 billion Gb). CPU-side LPDDR5X = racks × CPUs per rack × GB per CPU.

Notes by rack

GB200 NVL72

The first NVL72 rack. 192 GB per GPU works out to roughly 13.8 TB across the rack.

Basis: Capacity per GPU is public spec. Eight stacks per GPU and eight dies per stack are derived from capacity divided by the generation's per-stack size, not disclosed figures

GB300 NVL72

Physically each GPU sits next to 8 HBM3E stacks, 12 layers each at 3 GB a layer, which is 288 GB. That is what the memory maker actually ships. NVIDIA's spec page lists 279 GB, the capacity a user can address, and 279 times 72 is exactly the 20 TB it quotes for the rack. The missing 9 GB is not explained officially. Industry reading points to reserved capacity or a layer switched off for yield, neither confirmed. The cascade uses 288, because that 9 GB of silicon still got made.

Basis: 72 GPUs and 20 TB per rack come from NVIDIA's rack spec page. 288 GB per GPU comes from NVIDIA's enterprise reference architecture, which separately lists 2304 GB across an eight-GPU baseboard, and 2304 divided by eight is exactly 288. The 36 GB, 12-high, 24 Gb-per-die stack is Micron's own HBM3E product specification, confirmed by a TechInsights teardown of a physical B300 package. Neither company states stacks per GPU. Eight falls out of 288 divided by 36, so it is not an assumption but two companies' published figures reconciling.

Vera Rubin NVL72

Moves to HBM4, where the interface doubles from 1024 to 2048 bits. The GPU package is a dual-die design and the rack carries 20.7 TB, which divided by 72 is about 288 GB, so this generation shows none of the gap between physical and usable capacity that GB300 does. Micron has announced HBM4 in high volume production for Vera Rubin.

Basis: 288 GB per GPU and 20.7 TB per rack are public reporting. The 36 GB 12-high stack is from Micron's HBM4 volume production announcement. Eight stacks follows from 288 divided by 36. Micron is also sampling a 48 GB 16-high part, and a switch to that would change the stack count per GPU.

Rubin Ultra NVL576

NVL576 counts 576 compute dies at four dies per package, so there are 144 packages. Each package carries 1 TB of HBM4E. This generation is still moving, so treat the numbers as order of magnitude.

Basis: Forward-looking public reporting, not final. Stacks and dies per stack are derived, not disclosed

About this map
